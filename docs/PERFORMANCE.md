# 传输速度

旧版每发送 256 KiB 都等待接收确认。即使无线网络带宽很高，只要确认回传存在延迟，也会反复暂停。新版将分块增至 1 MiB，允许最多 8 MiB 已发送但尚未确认的数据连续流动，收到累计确认后释放窗口。发送端最终仍要收到全部字节确认及接收端 SHA-256 校验完成响应。

接收数据队列最多缓存 8 MiB，容量不足时暂停继续读取 socket，以 TCP 反压控制流量。进度按文件 ID 合并，完成或失败事件可靠投递，避免批量小文件时界面或自动更新误判还有未完成任务。应用显示的发送速度来自接收端确认的字节，接收速度来自已写入接收文件的字节。

## 可重复基准

在同一台 Mac 上，使用真实加密 TCP 传输 32 MiB 文件，并为每次累计确认增加 20 毫秒回传延迟。接收端执行与 v1.0.x 相同的协议，校验 SHA-256，比较保存文件与源文件全部字节。该条件用于测量等待确认的影响，不能代表任意 Wi-Fi 的实测带宽。

v1.1.0 发布前，在同一次基准里分别使用旧策略和新策略：

| 发送策略 | 完成时间 | 吞吐 | 分块数 | 最大等待确认数 |
| --- | ---: | ---: | ---: | ---: |
| 256 KiB，每块等待确认 | 3.0481 秒 | 10.498 MiB/s | 128 | 1 |
| 1 MiB，8 MiB 连续发送窗口 | 0.1254 秒 | 255.144 MiB/s | 32 | 8 |

该条件下约提升 24.3 倍。修改前的真实 v1.0.1 快照另外测得 2.8802 秒、11.110 MiB/s，与控制组一致。该结果来自本机加密 TCP 和人工确认延迟，实际两台 Mac 的 Wi-Fi 速度需实机对比，不能据此承诺 255 MiB/s 的无线带宽。

```sh
LANDROP_RUN_BENCHMARK=1 swift test --filter TransferPerformanceTests.testArtificialRTTBenchmark
```

基准默认跳过，以免将本机负载、磁盘缓存和调度抖动作为普通功能测试的通过条件。功能测试另外验证发送窗口上限、最终确认、旧协议收发、异常确认、超时、取消及慢进度消费者。

实际速度取决于两台 Mac 的网络、磁盘和文件大小。有线千兆或较好的 Wi-Fi 有助于提高上限；大量小文件、文件夹打包和最后的校验仍需要额外时间。建议用同一个大文件对比升级前后两台 Mac 上显示的持续速度。
